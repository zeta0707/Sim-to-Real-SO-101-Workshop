# OMX-F 실제 로봇 배포 (RL 정책 r10)

시뮬레이션에서 학습한 Cube-To-Cup 정책을 실제 OMX-F 에서 돌리는 제어 루프다. Isaac Sim 없이 numpy 만 쓴다.
카메라가 없으므로 큐브/컵 위치는 **사람이 정해 준 고정 좌표**를 쓴다 (로봇 베이스 기준 m, +x 앞, +y 왼쪽).

| 파일 | 역할 |
|---|---|
| `omx_real_run.py` | 30 Hz 제어 루프, 관측 33차원 생성, 안전장치, 보정/주차 도구 |
| `omx_policy_r10.npz` | 내보낸 정책 (actor 가중치 + 관측 정규화 통계) |
| `omx_kinematics.py` | OMX-F 순기구학 (시뮬레이션 ee 와 5e-7 m 일치) |
| `calib.json` | 이 로봇의 보정값 (관절 오프셋, 그리퍼 열림/닫힘, 주차 자세) |

## 빠른 사용법 (보정이 끝난 로봇)

1. 큐브를 정해 둔 좌표에, 컵을 정해 둔 위치에 놓는다. 큐브는 매번 **같은 방향**(면이 로봇 앞을 향하도록)으로 놓는다.
2. 아래 명령을 실행한다. 비상정지(전원)에 손이 닿는 곳에서, 처음 한두 번은 Ctrl-C 가까이에서 지켜본다.

```bash
python deploy/omx_real_run.py --io lerobot --port /dev/ttyACM0 --calib deploy/calib.json \
  --send --goto_home --home_secs 4 --action_scale 0.25 --grip_gain 1.5 \
  --cube_xy 0.232 -0.050 --cup_xy 0.179 0.110 --rule_cup_xy 0.156 0.100 \
  --lock_roll 0 --carry_z_min 0.165 --auto_release --release_tol 0.02 \
  --park --max_steps 400 --log run.npz
```

실행 순서: 시작 자세(관절 0)로 이동 → 접근 → 그리퍼 열기 → 내려가서 쥠 → 들어 올려 컵 위로 운반 → 컵 위에서 그리퍼 열기 → 수직 후퇴(z 0.24) → 저장된 주차 자세로 이동 → 토크 유지하고 종료.
로그 이름(`--log`)은 회차마다 바꾼다 (같은 이름은 덮어쓴다).

### 이 명령의 값이 뜻하는 것
| 옵션 | 값 | 의미 |
|---|---|---|
| `--cube_xy` | `0.232 -0.050` | 큐브 중심 좌표. **실제로 놓은 위치와 같아야 한다** (1 cm 이상 다르면 집기가 어긋난다) |
| `--cup_xy` | `0.179 0.110` | 정책에 알려 주는 컵 위치. 정책이 컵 중심에 못 미쳐 멈추는 경향을 보정하려고 실제 컵(0.156, 0.098)과 다르게 준다 |
| `--rule_cup_xy` | `0.156 0.100` | 놓기 규칙이 쓰는 실제 컵 중심 |
| `--action_scale` | `0.25` | 정책 행동 크기. 0.15 / 0.25 / 0.3 에서 각각 5/5 였고 0.25 를 권장 (0.4 는 시험하지 않음) |
| `--lock_roll` | `0` | 손목 롤을 0° 로 고정 (정책이 롤을 계속 돌리기 때문) |
| `--carry_z_min` | `0.165` | 운반 중 팔끝 최소 높이 (컵 림 위로 넘기기) |
| `--grip_gain` | `1.5` | 그리퍼 열림 폭 보정 |
| `--auto_release` | | 규칙형 놓기 (아래 참고) |
| `--park` | | 놓은 뒤 수직 후퇴 → 주차 자세 |

### 큐브 위치 바꾸기
`--cube_xy` 만 바꾼다 (컵 옵션은 컵이 그대로면 바꾸지 않는다). 학습 때 큐브 분포는 기본 위치 `(0.22, -0.04)` 에서 x, y ±3 cm (현재 소스는 ±5 cm, yaw ±0.8 rad) 이다. 먼 위치는 처음에 `--action_scale 0.15` 로 천천히 본다.
큐브 방향(yaw)은 입력할 수 없고 손목 롤도 잠겨 있으므로 항상 같은 방향으로 놓는다.

## 옵션 설명

### 보정/주차 (한 번만)
- `--probe`: 읽기 전용. 토크를 끄고 관절/그리퍼/팔끝 좌표를 계속 출력한다. 손으로 움직이며 값을 본다.
- `--calibrate`: 손으로 잡은 자세에서 관절 오프셋과 그리퍼 열림/닫힘 값을 `calib.json` 에 저장한다.
- `--trim` / `--trim_q`: 특정 자세에서 관절 오프셋을 미세 조정한다 (토크를 건 상태의 처짐에 주의).
- `--set_park`: 토크를 끄고, 손으로 주차 자세로 놓은 뒤 Enter 를 누르면 `calib.json` 의 `park_q` 에 저장한다.
- `--joint_sign`: 관절 방향이 시뮬레이션과 반대일 때 부호를 지정한다.

### 실행 중 동작
- `--goto_home`, `--home_secs`: 시작 시 시뮬레이션 시작 자세(관절 0, 그리퍼 닫힘)로 천천히 이동한다.
- `--grasp_dwell N`: 쥔 직후 N 스텝 동안 팔을 멈추고 그리퍼만 조인다 (들다 떨어짐 방지, 기본 20).
- `--auto_release`: 아래 두 조건 중 하나가 되면 정책 출력을 무시하고 그리퍼를 연다. 열리는 동안 팔은 정지한다.
  1. 팔끝이 컵 중심 `--release_tol` 안에 `--release_dwell` 스텝 머문다.
  2. 컵 중심 `--stall_radius`(0.045 m) 안에서 `--stall_steps`(30 스텝, 약 1초) 동안 팔끝이 거의 안 움직인다 (정책이 컵 위에서 멈춰 놓지 않을 때).
- `--park`: 놓은 뒤 그리퍼를 더 열지 않고 `--retreat_z`(0.24) 까지 수직 후퇴하고 `--park_secs`(6 s) 동안 주차 자세로 이동한다. **놓지 못했으면 주차하지 않고** 경고만 출력하고 현재 자세를 유지한다.
- `--retreat_open`: 후퇴 때 그리퍼 열림 값을 따로 지정한다 (기본은 열린 상태 그대로).
- `--max_steps`: 최대 스텝 (30 Hz). `--log`: 관측/행동/목표/팔끝을 `.npz` 로 저장.
- `--max_relative_target`: 스텝당 최대 이동량(기본 8°). "Relative goal position magnitude had to be clamped" 경고는 이 제한에 걸린 것이라 정상이다.

### 안전장치
- 기본은 **읽기 전용**이다. `--send` 를 줘야 명령이 나간다 (`--send` 없이 돌리면 팔은 움직이지 않는다).
- 팔끝 z 0.05 m 미만으로 내려가는 팔 동작은 거부한다. 거부가 45 스텝 연속이면 중단한다 (`--send` 일 때).
- 닫은 뒤에도 그리퍼가 계속 -0.10 rad 이하(빈 손)면 중단한다 (`--send` 일 때).
- Ctrl-C 는 토크를 유지한 채 끝난다. 놓기 전 중단했으면 큐브를 손으로 받쳐 준다.
- 중단되거나 놓지 못한 경우 주차하지 않는다.

## 처음 설정하는 로봇이라면

1. **로봇 없이 점검**: `python deploy/omx_real_run.py --selftest outputs/rl/ref_r10.npz` (FK / 정책 출력 / 가짜 로봇 루프).
2. **관절 보정**: 팔을 손으로 시뮬레이션 0 자세 근처에 놓고 `--calibrate` 를 실행한다. 토크를 건 상태에서 오래 두면 처짐이 섞이므로 손으로 들고 있는 상태의 값을 쓴다.
3. **그리퍼 확인**: `--probe` 로 완전히 열었을 때와 **큐브를 쥐었을 때**의 값을 본다. 큐브를 쥔 값이 시뮬레이션 0 rad 가 되도록 `gripper_closed_pos` 를 맞춘다.
4. **주차 자세 저장**: `--set_park`.
5. **단계별 시험** (앞 단계 통과 후 다음으로):

| 단계 | 내용 | 확인 |
|---|---|---|
| A | `--send` 없이 실행하고 손으로 팔을 움직여 본다 | 관측/행동이 튀지 않음, 팔끝 좌표가 눈으로 맞음 |
| B | `--send --goto_home --action_scale 0.15` (큐브 없음) | 관절 한계/책상 충돌 없음, 방향이 시뮬레이션과 같음 |
| C | 큐브를 놓고 같은 명령 | 큐브를 쥠 |
| D | 위의 "빠른 사용법" 명령 | 컵 안에 넣음 |
| E | 반복 5~10회, 회차마다 `--log` 이름을 바꿈 | 성공률 |

## 검증 결과 (큐브 (0.232, -0.050), 컵 중심 (0.156, 0.098), 같은 받침대 위)
action_scale 0.15 / 0.25 / 0.3 에서 각각 5/5 (큐브가 컵 안, 컵 충돌 없음). 컵은 높이 7 cm, 안쪽 반지름 약 4 cm 원형이다.
큐브와 컵은 같은 받침대(약 1.7 cm) 위에 둔다.

## 알아 둘 한계 (시뮬레이션과 다른 점)
- 큐브 위치는 상수다. 쥔 뒤에는 "쥔 순간의 상대 위치로 팔끝에 붙어 있다"고 가정한다 (`ObsBuilder`). 큐브가 미끄러져도 정책은 모른다.
- 큐브 방향(yaw)은 모르고, 손목 롤은 고정이다. 큐브를 항상 같은 방향으로 놓아야 한다.
- 정책이 컵 위에서 중심에 못 미쳐 멈춘다 (팔끝이 컵 중심보다 로봇 쪽 약 2.5 cm). 그래서 `--auto_release` 의 정지 규칙이 필요하고, 큐브는 중심에서 약간 벗어나 떨어진다.
- 실제 로봇은 중력/백래시로 처진다 (명령 대비 팔끝 z 약 8 mm). 관절 오프셋은 손으로 든 자세에서 보정한 값이다.
- 관절 속도는 유한 차분(저역통과)으로 추정한다. 시뮬레이션의 속도와 분포가 다르다.
- 모터 PD/지연/마찰이 시뮬레이션과 다르다. `--log` 기록을 시뮬레이션과 비교해서 어긋남을 본다.
